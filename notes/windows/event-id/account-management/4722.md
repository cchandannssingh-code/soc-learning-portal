# Windows Security Event ID 4722 - User Account Enabled

## Overview

**Event ID:** 4722

**Log Source:** Security

**Category:** User Account Management

**Description:** A user account was enabled.

---

## Why is this Important?

Event ID 4722 indicates that a previously disabled account has been enabled and can now be used for authentication.

Attackers may enable:

* Dormant accounts
* Disabled administrative accounts
* Previously created backdoor accounts

Therefore, this event is commonly monitored in SOC environments.

---

## Key Fields

| Field                | Description                           |
| -------------------- | ------------------------------------- |
| Subject Account Name | User who enabled the account          |
| Subject Security ID  | SID of the user performing the action |
| Logon ID             | Session that performed the action     |
| Target Account Name  | Account that was enabled              |
| Target Security ID   | SID of the enabled account            |

---

## Example Event

### Subject (Who Enabled the Account)

```text
Security ID: DOMAIN\AdminUser
Account Name: AdminUser
```

The account **AdminUser** performed the action.

### Target Account

```text
Security ID: DOMAIN\john
Account Name: john
```

The account **john** was enabled.

---

## What Does It Mean?

Before:

```text
john = Disabled
```

After Event ID 4722:

```text
john = Enabled
```

The account can now authenticate and access resources according to its permissions.

---

## Investigation Steps

### Step 1: Verify Who Enabled the Account

Check:

```text
Subject Account Name
```

Questions:

* Is this an authorized administrator?
* Was there a valid request or ticket?
* Is the action expected?

---

### Step 2: Determine Why the Account Was Disabled

Review earlier events:

```text
4725 - User Account Disabled
```

Questions:

* Was the account disabled due to termination?
* Was it disabled due to inactivity?
* Was it disabled for security reasons?

---

### Step 3: Check Recent Account Creation

Search for:

```text
4720 - User Account Created
```

Common sequence:

```text
4720 -> Account Created
4722 -> Account Enabled
```

This is normal during user onboarding.

---

### Step 4: Check Password Activity

Search for:

```text
4723 - Password Change
4724 - Password Reset
```

---

### Step 5: Check Group Membership Changes

Search for:

```text
4728 - Added to Security Group
4732 - Added to Local Group
4756 - Added to Universal Group
```

Determine whether the account gained elevated privileges.

---

### Step 6: Check Logon Activity

Search for:

```text
4624 - Successful Logon
4625 - Failed Logon
```

Look for logons shortly after the account was enabled.

---

## Common Scenarios

### Legitimate

* New employee onboarding
* Contractor reactivation
* Service account activation
* User returned from leave

### Suspicious

* Disabled admin account suddenly enabled
* Unknown user enabling accounts
* Account enabled outside business hours
* Account enabled and immediately added to Domain Admins
* Account enabled and used from unusual systems

---

## SOC Analyst Summary


> User "AdminUser" enabled the account "john".

## Interview Answer

**Q: What does Event ID 4722 indicate?**

**Answer:**

Event ID 4722 indicates that a previously disabled user account was enabled. During investigation, I would verify who enabled the account, whether the action was authorized, and whether the account was subsequently used for logon or granted additional privileges.
