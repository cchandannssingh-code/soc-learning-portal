# Windows Security Event ID 4724 - An Attempt Was Made to Reset an Account's Password

## Overview

**Event ID:** 4724

**Log Source:** Security

**Category:** User Account Management

**Description:** An attempt was made to reset the password of an account.

---

## What Does It Mean?

Event ID 4724 occurs when one user resets the password of another user.

This is commonly performed by:

* Helpdesk staff
* Domain Administrators
* System Administrators
* Identity Management Systems

---

## Password Change vs Password Reset

| Event ID | Action                           |
| -------- | -------------------------------- |
| 4723     | User changes their own password  |
| 4724     | Another user resets the password |

### Easy Way to Remember

```text
4723 = I changed my password
4724 = Someone reset my password
```

---

## Key Fields

| Field                | Description                   |
| -------------------- | ----------------------------- |
| Subject Account Name | User performing the reset     |
| Target Account Name  | User whose password was reset |
| Logon ID             | Session performing the action |

---

## Example Event

### Subject (Who Performed the Reset)

```text
Security ID: DOMAIN\AdminUser
Account Name: AdminUser
```

### Target Account

```text
Security ID: DOMAIN\john
Account Name: john
```

Meaning:

> AdminUser reset the password of john.

---

## How to Interpret

### Normal Activity

```text
Subject = AdminUser
Target  = john
```

A helpdesk or administrator reset the user's password.

---

### Suspicious Activity

```text
Subject = unknown_user
Target  = Administrator
```

Potential signs of compromise:

* Unauthorized password reset
* Insider threat
* Privilege escalation attempt
* Lateral movement

---

## Investigation Steps

### Step 1: Identify Who Reset the Password

Check:

```text
Subject Account Name
```

Questions:

* Is this user authorized?
* Is there a valid ticket/request?
* Is the action expected?

---

### Step 2: Identify the Target User

Check:

```text
Target Account Name
```

Questions:

* Is it a privileged account?
* Is it a service account?
* Is it a normal user account?

---

### Step 3: Review Recent Logons

Search for:

```text
4624 - Successful Logon
4625 - Failed Logon
```

Determine where the reset originated.

---

### Step 4: Check for Privilege Escalation

Search for:

```text
4728 - Added to Security Group
4732 - Added to Local Group
4756 - Added to Universal Group
```

---

### Step 5: Check Subsequent Logon Activity

After a password reset, search for:

```text
4624
```

Questions:

* Did the account immediately log in?
* Was the login expected?
* Was the source system normal?

---

## Common Attack Scenario

An attacker compromises an admin account and resets another user's password.

Attack chain:

```text
4624 -> 4724 -> 4728 -> 4624
Login -> Password Reset -> Add Privileges -> Login
```

This can indicate:

* Account takeover
* Persistence
* Privilege escalation

**Q: What does Event ID 4724 indicate?**

**Answer:**

Event ID 4724 indicates that a user attempted to reset another user's password. During investigation, I would verify who performed the reset, whether they were authorized, identify the target account, review recent logon activity, and check for any suspicious actions such as privilege escalation or account misuse following the reset.
