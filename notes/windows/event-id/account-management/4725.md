# Windows Security Event ID 4725 - A User Account Was Disabled

## Overview

**Event ID:** 4725

**Log Source:** Security

**Category:** User Account Management

**Description:** A user account was disabled.

---

## What Does It Mean?

Event ID 4725 is generated when a user account is disabled.

Once disabled:

* The user cannot log in.
* Existing permissions remain assigned.
* The account becomes inactive until re-enabled.

---

## Why is it Important?

Account disabling is a common administrative action, but attackers may also disable accounts to:

* Disrupt operations
* Lock out legitimate users
* Hide malicious activity
* Disable security or service accounts

---

## Key Fields

| Field                | Description                           |
| -------------------- | ------------------------------------- |
| Subject Account Name | User who disabled the account         |
| Subject Security ID  | SID of the user performing the action |
| Target Account Name  | Account that was disabled             |
| Target Security ID   | SID of the disabled account           |

---

## Example Event

### Subject (Who Disabled the Account)

```text
Security ID: DOMAIN\AdminUser
Account Name: AdminUser
```

### Target Account

```text
Security ID: DOMAIN\john
Account Name: john
```

Meaning:

> AdminUser disabled the account john.

---

## How to Interpret

### Normal Activity

```text
AdminUser disabled john
```

Common reasons:

* Employee termination
* User resignation
* Temporary suspension
* Security investigation
* Account cleanup

---

### Suspicious Activity

```text
UnknownUser disabled Administrator
```

Potential indicators:

* Insider threat
* Compromised admin account
* Attack preparation
* Denial of service against legitimate users

---

## Investigation Steps

### Step 1: Identify Who Disabled the Account

Check:

```text
Subject Account Name
```

Questions:

* Is this an administrator?
* Was the action authorized?
* Is there a supporting ticket or request?

---

### Step 2: Identify the Target Account

Check:

```text
Target Account Name
```

Questions:

* Is it a normal user account?
* Is it a privileged account?
* Is it a service account?

---

### Step 3: Check Recent Activity

Search for:

```text
4624 - Successful Logon
4625 - Failed Logon
```

Review activity before the account was disabled.

---

### Step 4: Check for Related Account Changes

Search for:

```text
4738 - Account Modified
4726 - Account Deleted
4722 - Account Enabled
```

Possible sequence:

```text
4725 -> 4722
Disabled -> Enabled
```

---

### Step 5: Review Privileged Accounts

If the target account is:

```text
Administrator
Domain Admin
Service Account
```

Treat the event with higher priority.

---

## Common Attack Scenario

An attacker gains administrative access and disables legitimate accounts.

Example chain:

```text
4624 -> 4725 -> 4732
Logon -> Disable User -> Modify Groups
```

Potential objectives:

* Prevent detection
* Lock out administrators
* Maintain persistence

**Q: What does Event ID 4725 indicate?**

**Answer:**

Event ID 4725 indicates that a user account was disabled. During investigation, I would verify who disabled the account, whether the action was authorized, identify the affected account, review recent account activity, and check for any related account modifications or suspicious behavior.
