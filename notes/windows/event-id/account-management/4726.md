# Windows Security Event ID 4726 - A User Account Was Deleted

## Overview

**Event ID:** 4726

**Log Source:** Security

**Category:** User Account Management

**Description:** A user account was deleted.

---

## What Does It Mean?

Event ID 4726 is generated when a user account is permanently deleted from the system or Active Directory.

Once deleted:

* The account can no longer be used.
* The SID is removed from active use.
* User access is permanently revoked.
* Recovery may require restoring from Active Directory Recycle Bin or backup.

---

## Why is it Important?

Account deletion is a high-impact administrative action.

It may indicate:

### Legitimate Activity

* Employee offboarding
* Account cleanup
* Removal of temporary accounts
* Decommissioning service accounts

### Suspicious Activity

* Covering tracks after compromise
* Deleting security accounts
* Removing evidence
* Insider threat activity

---

## Key Fields

| Field                | Description                             |
| -------------------- | --------------------------------------- |
| Subject Account Name | User who deleted the account            |
| Subject Security ID  | SID of the user performing the deletion |
| Target Account Name  | Deleted account                         |
| Target Security ID   | SID of deleted account                  |

---

## Example Event

### Subject (Who Deleted the Account)

```text
Security ID: DOMAIN\AdminUser
Account Name: AdminUser
```

### Target Account

```text
Security ID: DOMAIN\john
Account Name: john
```

Meaning:

> AdminUser deleted the account john.

---

## How to Interpret

### Normal Activity

```text
AdminUser deleted john
```

Possible reasons:

* Employee left organization
* Duplicate account removal
* Temporary account cleanup
* Account lifecycle management

---

### Suspicious Activity

```text
UnknownUser deleted Administrator
```

Potential indicators:

* Compromised administrator account
* Insider threat
* Malicious account removal
* Evidence destruction

---

## Investigation Steps

### Step 1: Identify Who Deleted the Account

Check:

```text
Subject Account Name
```

Questions:

* Is the user authorized?
* Was a ticket/request approved?
* Is the action expected?

---

### Step 2: Identify the Deleted Account

Check:

```text
Target Account Name
```

Questions:

* Was it a privileged account?
* Was it a service account?
* Was it a normal user account?

---

### Step 3: Review Recent Activity of Deleted Account

Search for:

```text
4624 - Successful Logon
4625 - Failed Logon
```

Check what the account was doing before deletion.

---

### Step 4: Check Account Lifecycle Events

Search for:

```text
4720 - Account Created
4722 - Account Enabled
4725 - Account Disabled
4738 - Account Modified
```

Typical legitimate sequence:

```text
4720 -> 4722 -> 4725 -> 4726
Create -> Enable -> Disable -> Delete
```

---

### Step 5: Review Privileged Account Deletions

If the deleted account belongs to:

```text
Administrator
Domain Admin
Enterprise Admin
Service Account
```

Treat the event as high priority.

---

## Common Attack Scenario

An attacker gains administrative access and removes accounts to hide activity.

Example attack chain:

```text
4624 -> 4738 -> 4726
Logon -> Modify Account -> Delete Account
```

Possible objectives:

* Destroy evidence
* Remove legitimate administrators
* Prevent incident response

**Q: What does Event ID 4726 indicate?**

**Answer:**

Event ID 4726 indicates that a user account was deleted. During investigation, I would verify who deleted the account, determine whether the deletion was authorized, identify the affected account, review recent activity associated with the account, and check for any suspicious account management actions leading up to the deletion.
