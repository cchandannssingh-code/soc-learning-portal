# Windows Security Event ID 4728 - A Member Was Added to a Security-Enabled Global Group

## Overview

**Event ID:** 4728

**Log Source:** Security

**Category:** Group Management

**Description:** A member was added to a security-enabled global group.

---

## What Does It Mean?

Event ID 4728 is generated when a user, computer, or group is added to a **Security Global Group** in Active Directory.

This is one of the most important privilege escalation events monitored by SOC teams.

---

## Why is it Important?

Attackers often add compromised accounts to privileged groups to gain elevated permissions.

Examples:

* Domain Admins
* Enterprise Admins
* Account Operators
* Backup Operators
* Custom privileged groups

---

## Key Fields

| Field                | Description                 |
| -------------------- | --------------------------- |
| Subject Account Name | User who added the member   |
| Member Name          | User/group that was added   |
| Group Name           | Target security group       |
| Group Domain         | Domain containing the group |

---

## Example Event

### Subject (Who Added the User)

```text
Security ID: DOMAIN\AdminUser
Account Name: AdminUser
```

### Member Added

```text
Member Name: CN=john,CN=Users,DC=domain,DC=com
```

### Target Group

```text
Group Name: Domain Admins
```

Meaning:

> AdminUser added john to the Domain Admins group.

---

## How to Interpret

### Normal Activity

```text
AdminUser added john to HelpDesk Group
```

Examples:

* User onboarding
* Role changes
* Team transfers

---

### High-Risk Activity

```text
AdminUser added john to Domain Admins
```

This grants powerful privileges.

SOC analysts should immediately validate:

* Was the change authorized?
* Was there a ticket/change request?
* Is the account expected to have admin privileges?

---

## Investigation Steps

### Step 1: Identify Who Performed the Action

Check:

```text
Subject Account Name
```

Questions:

* Is this a domain administrator?
* Was the action expected?
* Is there an approved request?

---

### Step 2: Identify the Added Member

Check:

```text
Member Name
```

Questions:

* Is it a user account?
* Is it a service account?
* Is it a recently created account?

---

### Step 3: Identify the Target Group

Check:

```text
Group Name
```

Examples of high-value groups:

```text
Domain Admins
Enterprise Admins
Administrators
Account Operators
Backup Operators
```

---

### Step 4: Review Account History

Search for:

```text
4720 - Account Created
4722 - Account Enabled
4738 - Account Modified
4624 - Successful Logon
```

Common attacker chain:

```text
4720 -> 4722 -> 4728 -> 4624
Create -> Enable -> Add to Admin Group -> Logon
```

---

### Step 5: Review Logon Activity

Search:

```text
4624
```

Questions:

* Did the account log in after receiving privileges?
* From which host?
* Was the source system expected?

---

## Common Attack Scenario

### Privilege Escalation

Attacker compromises a standard user account.

Then:

```text
4728
```

adds the account to:

```text
Domain Admins
```

Result:

```text
Full Domain Administrative Access
```

This is a critical alert in most SOC environments.

**Q: What does Event ID 4728 indicate?**

**Answer:**

Event ID 4728 indicates that a member was added to a security-enabled global group. During investigation, I would identify who performed the action, determine which user was added, verify the target group, and assess whether the membership change could result in privilege escalation, especially if the group is Domain Admins or another privileged group.
