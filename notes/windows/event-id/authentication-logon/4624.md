# Windows Security Event ID 4624 - An Account Was Successfully Logged On

## Overview

| Field       | Value                                                                         |
| ----------- | ----------------------------------------------------------------------------- |
| Event ID    | 4624                                                                          |
| Log Source  | Security                                                                      |
| Category    | Authentication / Logon                                                        |
| Severity    | Informational (Can become High/Critical depending on context)                 |
| Description | Generated whenever an account successfully authenticates to a Windows system. |

---

## What Does It Mean?

Event ID 4624 indicates that a user, computer account, service account, or application successfully authenticated to a Windows system.

This event confirms that Windows accepted the credentials and granted access to a session.

Think of Event ID 4624 as:

> "Authentication succeeded."

It does **not necessarily mean a user logged in interactively**.

Many activities generate Event ID 4624:

* User login
* RDP login
* SMB file access
* Service startup
* Scheduled task execution
* Application authentication
* RunAs activity

---

## Why Is It Important?

Event ID 4624 is one of the most important Windows Security events because it helps identify:

* Who accessed a system
* When access occurred
* How authentication happened
* Whether privileged access was obtained
* Whether suspicious remote access occurred

---

### Legitimate Reasons

* User signs into workstation
* Administrator logs into server
* User accesses network share
* Service account starts service
* Scheduled task executes
* Application authenticates user

---

### Suspicious Reasons

* Lateral movement
* Pass-the-Hash attacks
* Unauthorized RDP access
* Stolen credential usage
* Service account abuse
* Privilege escalation activity
* Persistence mechanisms

---

## Easy Memory Trick

```text
4624 = Successful Logon
4625 = Failed Logon
```

Another way:

```text
24 = Access Granted
25 = Access Denied
```

```text

```

# Why SOC Analysts Care About 4624

Most attack chains contain Event ID 4624 somewhere.

Example:

```text
Initial Access
      ↓
4624
      ↓
Privilege Escalation
      ↓
4672
      ↓
Lateral Movement
```

Without Event ID 4624, most attacker activity cannot occur.

# Subject Section

## What Is Subject?

The Subject section identifies:

> Who initiated the action.

Think of it as:

> "Who performed this activity?"

---

## Security ID

### Purpose

Unique SID of the account that performed the action.

Example:

```text
DOMAIN\AdminUser
```

or

```text
S-1-5-21-123456789-123456789-123456789-500
```

---

### Why It Matters

Usernames can change.

SIDs remain unique.

During investigations, SID is often more reliable than username.

Useful for:

* Threat hunting
* User tracking
* Historical investigations
* Account renaming investigations

---

### Common Values

| Value           | Meaning                  |
| --------------- | ------------------------ |
| DOMAIN\User     | Domain User              |
| COMPUTER\User   | Local User               |
| SYSTEM          | Local System             |
| LOCAL SERVICE   | Built-in Service Account |
| NETWORK SERVICE | Built-in Network Account |
| S-1-0-0         | NULL SID                 |

---

### NULL SID Example

```text
S-1-0-0
```

Meaning:

Windows could not associate the action with a user.

Common during:

* System startup
* Internal authentication processes
* Machine-generated events

Usually normal.

### Purpose

## Restricted Admin Mode

Primarily used with RDP.

---

### Restricted Admin Mode = Yes

Example:

```text
Restricted Admin Mode: Yes
```

Meaning:

Credentials were NOT delegated.

Benefits:

* Prevents credential theft
* Protects against credential dumping
* Reduces lateral movement opportunities

Generally positive.

---

### Restricted Admin Mode = No

Most common value.

Traditional authentication behavior.

Normal in most environments.

---

## Virtual Account

Indicates whether Windows used a virtual service account.

---

### Virtual Account = Yes

Example:

```text

```

```text

```

Meaning:

Windows-created service identity.

Usually expected.

---

### Virtual Account = No

Most common value.

Standard:

* User account
* Domain account
* Service account

---

## Elevated Token

One of the most important fields.

Indicates whether user possesses administrative privileges.

---

### Elevated Token = Yes

Example:

```text
Elevated Token: Yes
```

Meaning:

Administrative privileges available.

Examples:

```text
Administrator
```

```text
Domain Admin
```

```text
Server Admin
```

or

```text
User approved UAC prompt
```

---

### Why Analysts Care

Attackers want elevated sessions.

Common attack flow:

```text

     ↓
4672
     ↓
Administrative Access
```

---

### Elevated Token = No

Meaning:

Standard user privileges.

No administrative token available.

Lower risk.

---

## Analyst Investigation Questions

If Elevated Token = Yes:

* Is user expected to have admin rights?
* Is source IP trusted?
* Is login time normal?
* Is RDP involved?
* Was MFA enforced?

# Impersonation Level Deep Dive

## What Is Impersonation?

Impersonation allows a process or service to act on behalf of another user.

Think of it as:

> "How much authority does Windows allow this process to use when acting as the authenticated user?"

This field becomes important during:

* Kerberos investigations
* Delegation investigations
* Lateral movement investigations
* Service authentication reviews

---

## Impersonation Levels

| Level          | Meaning                  | Risk   |
| -------------- | ------------------------ | ------ |
| Anonymous      | Cannot identify user     | Low    |
| Identification | Can identify user only   | Low    |
| Impersonation  | Can act as user locally  | Medium |
| Delegation     | Can act as user remotely | High   |

---

## Anonymous

Example:

```text
Impersonation Level: Anonymous
```

Meaning:

* Server cannot identify user.
* User context unavailable.

Rarely seen.

---

## Identification

Example:

```text
Impersonation Level: Identification
```

Meaning:

* Server knows who user is.
* Cannot perform actions as that user.

Generally low risk.

---

## Impersonation

Example:

```text
Impersonation Level: Impersonation
```

Most common value.

Meaning:

* Service can perform actions locally as authenticated user.
* Cannot access remote resources as user.

Normally expected.

---

### Example

```text
User Accesses Web Application
            ↓
Application Acts As User
            ↓
Local Resource Access
```

Normal behavior.

---

## Delegation

Example:

```text
Impersonation Level: Delegation
```

Most interesting value.

Meaning:

* Service can act as user on other systems.

---

### Example

```text
User
 ↓
Web Server
 ↓
Database Server
```

Web server can forward user credentials.

---

### Why SOC Analysts Care

Delegation is frequently abused.

Associated with:

* Kerberos Delegation Abuse
* Constrained Delegation Abuse
* Resource-Based Constrained Delegation
* Lateral Movement

---

### Investigation Questions

* Is delegation expected?
* Is service trusted?
* Is privileged account involved?
* Was delegation recently configured?

# Authentication Package

## Purpose

Protocol used for authentication.

---

## Common Values

| Value     | Meaning                  |
| --------- | ------------------------ |
| Kerberos  | Modern AD Authentication |
| NTLM      | Legacy Authentication    |
| Negotiate | Chooses Kerberos or NTLM |

---

## Kerberos

Preferred.

More secure.

Expected in domain environments.

---

### Common Related Events

```text
4768
```

```text
4769
```

```text
4771
```

---

## NTLM

Legacy protocol.

More heavily monitored.

Common during:

* Legacy Applications
* Workgroup Authentication
* Pass-the-Hash

---

### Analyst Questions

* Why NTLM?
* Why not Kerberos?
* Is system legacy?
* Is downgrade occurring?

---

## Negotiate

Meaning:

Windows chooses:

```text
Kerberos
```

or

```text
NTLM
```

depending on environment.

Normal.

---

## Package Name (NTLM Only)

Appears primarily with NTLM.

---

### NTLM V2

Example:

```text
NTLM V2
```

Preferred.

Normal.

---

### NTLM V1

Example:

```text
NTLM V1
```

High Risk.

Weak protocol.

Should be disabled.

---

## Key Length

### Purpose

Encryption key size used by NTLM.

---

### Example

```text
128
```

Stronger session protection.

---

### Key Length = 56

Older environments.

Less desirable.

---

### Key Length = 0

Most misunderstood value.

Example:

```text
Key Length: 0
```

Common with:

```text
Kerberos
```

Usually means:

> NTLM session key not applicable.

Not suspicious.

# Investigation Methodology

## Analyst Workflow

When investigating Event ID 4624, always follow this sequence:

```text
Who Logged In?
        ↓
How Did They Log In?
        ↓
Where Did They Log In From?
        ↓
What Privileges Did They Have?
        ↓
What Did They Do Next?
```

---

# Step 1 - Identify The User

Review:

```text
New Logon:
    Security ID
    Account Name
    Account Domain
```

Questions:

* Is the account legitimate?
* Is it a privileged account?
* Is it a service account?
* Is it newly created?
* Is it normally active?

---

## Example

```text
Account Name:
Administrator
```

Higher interest.

---

```text
Account Name:
svc_sql
```

Service account.

Should normally not perform interactive logins.

---

# Step 2 - Determine Logon Type

Review:

```text
Logon Type
```

Priority:

```text
Type 10
```

Highest Priority

```text
Type 3
```

High Priority

```text
Type 9
```

Medium/High Priority

```text
Type 2
```

Usually Lower Priority

---

## Questions

* Why was this logon type used?
* Is it normal for this account?
* Has this account used this logon type before?

---

# Step 3 - Review Source System

Review:

```text
Workstation Name
Source Network Address
```

Questions:

* Is source host trusted?
* Is source host managed?
* Is source IP known?
* Is source IP internal?
* Is source IP external?

---

# Step 4 - Review Authentication Method

Review:

```text
Authentication Package
```

Examples:

```text
Kerberos
```

Expected.

---

```text
NTLM
```

Higher interest.

---

Questions:

* Why NTLM?
* Why not Kerberos?
* Is application legacy?
* Is downgrade occurring?

---

# Step 5 - Check Privileges

Review:

```text
Elevated Token
```

and

```text
4672
```

Questions:

* Did administrative access occur?
* Is user expected to have elevated rights?
* Was privilege escalation involved?

---

# Step 6 - Review Activity After Login

Search:

```text
4688
```

Process Creation

```text
5140
```

Network Share Access

```text
5145
```

Detailed Share Access

```text
4672
```

Special Privileges

Questions:

* What happened after authentication?
* Was suspicious execution observed?
* Was data accessed?

---

# Common Attack Scenarios

## Scenario 1 - RDP Lateral Movement

### Attack Chain

```text
4624 Type 10
      ↓
4672
      ↓
4688
```

---

### What Happened?

Attacker:

* Obtained credentials
* Logged in via RDP
* Received privileges
* Executed commands

---

### Investigation Questions

* Is source IP trusted?
* Was MFA used?
* Is account authorized?

---

# Common Analyst Mistakes

## Mistake 1

```text
Type 3 Always Means Lateral Movement
```

Reality:

Most Type 3 logins are normal SMB activity.

---

## Mistake 2

```text
NTLM Always Means Attack
```

Reality:

Many legacy applications still use NTLM.

---

## Mistake 3

```text
Blank Source IP Is Suspicious
```

Reality:

Local logins commonly show:

```text
-
```

---

## Mistake 4

```text
Ignoring Elevated Token
```

Reality:

Privilege context changes severity.

---

## Mistake 5

```text
Ignoring Logon ID
```

Reality:

Logon ID often reveals entire attack chain.

---

## Mistake 6

```text
Ignoring Process Name
```

Reality:

Process often reveals execution method.

# Interview Questions

## Q1. What does Event ID 4624 indicate?

### Answer

Event ID 4624 indicates that an account successfully authenticated to a Windows system.

---

## Q2. Which field is most important?

### Answer

There is no single most important field.

However analysts commonly prioritize:

```text
Logon Type
Account Name
Source IP
Authentication Package
Elevated Token
```

---

## Q3. Which Logon Types are most suspicious?

### Answer

```text
Type 3
```

Network Logon

and

```text
Type 10
```

RDP Logon

because attackers frequently use them during lateral movement.

---

## Q4. Why is Elevated Token important?

### Answer

It indicates whether administrative privileges were available.

---

## Q5. Why should analysts care about NTLM?

### Answer

NTLM is a legacy authentication protocol commonly observed during:

* Pass-the-Hash
* Legacy application authentication
* Authentication downgrade scenarios
