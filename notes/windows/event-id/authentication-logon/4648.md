# Windows Security Event ID 4648 - A Logon Was Attempted Using Explicit Credentials

## Overview

| Field       | Value                                                                                                     |
| ----------- | --------------------------------------------------------------------------------------------------------- |
| Event ID    | 4648                                                                                                      |
| Log Source  | Security                                                                                                  |
| Category    | Authentication / Credential Usage                                                                         |
| Severity    | Informational (Can become High/Critical depending on context)                                             |
| Description | Generated when a user, process, or application explicitly supplies credentials to attempt authentication. |

---

## What Does It Mean?

Event ID 4648 indicates that credentials were explicitly supplied during an authentication attempt.

Unlike Event ID 4624, this event does NOT confirm successful authentication.

It only confirms:

> Someone provided credentials for an authentication attempt.

Authentication may later:

```text
Succeed
    ↓
4624
```

or

```text
Fail
    ↓
4625
```

---

## Why Is It Important?

Event ID 4648 is extremely useful because it often appears before:

* Remote administration
* RDP connections
* RunAs commands
* PsExec execution
* Scheduled task execution
* Service account authentication
* Lateral movement activity

---

### Legitimate Reasons

* Administrator using RunAs
* User opening Remote Desktop
* SQL client connecting to database
* Backup software authenticating
* Management tools using alternate credentials

---

### Suspicious Reasons

* Credential theft
* Pass-the-Hash
* Lateral movement
* Privileged account abuse
* Service account misuse
* Unauthorized remote administration

---

## Easy Memory Trick

```text
4624 = Authentication Succeeded
4625 = Authentication Failed
4648 = Credentials Explicitly Supplied
```

Think:

```text
4648
   ↓
Credential Usage

4624
   ↓
Success

4625
   ↓
Failure
```

# Authentication Flow

```text
User Provides Credentials
          ↓
Event ID 4648
          ↓
Authentication Attempt
          ↓
4624 or 4625
```

# Why SOC Analysts Care About 4648

Many attack chains begin with credential usage.

Example:

```text
Credential Theft
       ↓
4648
Credentials Used
       ↓
4624
Authentication Success
       ↓
4672
Privileges Assigned
       ↓
4688
Command Execution
```

Without credentials being supplied, many attacker techniques cannot proceed.

# Example Event

## Raw Event

```text
Subject:
    Security ID:        S-1-5-21-XXXXXXXX-XXXXXXXX-XXXXXXXX-12345
    Account Name:       UserA
    Account Domain:     CONTOSO
    Logon ID:           0x6EE074
    Logon GUID:         {8baefcaa-5f72-0975-7591-a2e20da5dc12}

Account Whose Credentials Were Used:
    Account Name:       UserB
    Account Domain:     CONTOSO
    Logon GUID:         {00000000-0000-0000-0000-000000000000}

Target Server:
    Target Server Name: SERVER01
    Additional Information: SERVER01

Process Information:
    Process ID:         0x1AA0
    Process Name:       C:\Program Files\Application\app.exe

Network Information:
    Network Address:
    Port:
```

---

# Plain English Interpretation

This event indicates:

> UserA supplied credentials for UserB through app.exe while attempting authentication against SERVER01.

This event alone does not indicate success or failure.

To determine the result, search for:

```text
4624
```

or

```text
4625
```

immediately after the event.

# Analyst Deep Dive

## Why This Section Matters

Many analysts know that Event ID 4648 means:

```text id="3v7qcm"
Explicit Credentials Used
```

However, experienced analysts investigate:

* Who supplied credentials?
* Which credentials were supplied?
* Which application used them?
* Which system was targeted?
* Did authentication succeed afterward?
* Is this normal administrative behavior?

---

# Subject Section

## What Is Subject?

The Subject identifies:

> Who initiated the authentication request.

Think:

```text id="4x6vmb"
Who Started The Process?
```

Not:

```text id="e4yibn"
Who Logged In?
```

That distinction is very important.

---

## Security ID

### Purpose

Unique SID of the account that initiated the request.

Example:

```text id="2uxj8m"
S-1-5-21-XXXXXXXX-XXXXXXXX-XXXXXXXX-12345
```

---

### Why It Matters

SIDs remain consistent even if usernames change.

Useful for:

* Historical investigations
* Threat hunting
* Account tracking

---

### Common Values

| Value           | Meaning                  |
| --------------- | ------------------------ |
| DOMAIN\User     | Domain Account           |
| COMPUTER\User   | Local Account            |
| SYSTEM          | Local System             |
| LOCAL SERVICE   | Built-in Service         |
| NETWORK SERVICE | Built-in Network Account |

---

## Account Name

### Purpose

Account initiating the request.

Example:

```text id="0y4ww6"
UserA
```

---

### Investigation Questions

* Is account expected?
* Is account privileged?
* Is account compromised?
* Is account normally active?

---

### Important Concept

Subject account is NOT always the same as the credentials being used.

Example:

```text id="4ecxzx"
Subject:
Account Name = John
```

But:

```text id="chhv0r"
Account Whose Credentials Were Used:
Account Name = Administrator
```

Meaning:

```text id="el5kzl"
John
  ↓
Used
  ↓
Administrator Credentials
```

This is often high-interest activity.

---

## Account Domain

### Purpose

Shows where initiating account exists.

Example:

```text id="kzxukm"
CONTOSO
```

Domain Account.

---

```text id="23wxr5"
WORKSTATION01
```

Local Account.

---

## Logon ID

### Purpose

Unique session identifier.

Example:

```text id="7h0s7y"
0x6EE074
```

---

### Why It Matters

Allows correlation with:

```text id="xxh56w"
4624
```

```text id="0xiz0s"
4672
```

```text id="0z9nha"
4688
```

Events generated by same session.

---

## Logon GUID

### Purpose

Unique identifier used for authentication correlation.

Example:

```text id="5xvvya"
{8baefcaa-5f72-0975-7591-a2e20da5dc12}
```

---

### Why It Matters

Can correlate:

```text id="67ysvp"
4648
```

with:

```text id="x8gkpq"
4624
```

```text id="pk9qrx"
4768
```

```text id="rmnkp7"
4769
```

---

### Blank Logon GUID

Example:

```text id="h5f8zu"
{00000000-0000-0000-0000-000000000000}
```

Very common.

Usually means:

```text id="a0qv6v"
GUID Not Available
```

Not suspicious.

# Investigation Methodology

## Analyst Workflow

When investigating Event ID 4648, follow this sequence:

```text
Who Initiated Request?
          ↓
Which Credentials Were Used?
          ↓
Which Process Used Them?
          ↓
Which System Was Targeted?
          ↓
Did Authentication Succeed?
          ↓
What Happened Next?
```

---

# Interview Questions

## Q1. What does Event ID 4648 indicate?

### Answer

Event ID 4648 indicates that a user, process, or application explicitly supplied credentials to attempt authentication. It does not confirm success or failure.

---

## Q2. What is the most important investigation step?

### Answer

Determine whether authentication succeeded or failed by correlating Event ID 4648 with:

```text
4624
```

or

```text
4625
```

---

## Q3. Which fields are most important?

### Answer

Review:

```text
Subject Account
```

```text
Credentials Used
```

```text
Target Server
```

```text
Process Name
```

```text
4624 / 4625 Correlation
```

---

## Q4. Why is Process Name important?

### Answer

It identifies the application that supplied credentials and often reveals the authentication method used.

---

## Q5. Why do attackers generate Event ID 4648?

### Answer

Many attacker techniques require supplying credentials, including:

* RunAs abuse
* Lateral movement
* PsExec
* Pass-the-Hash
* Remote administration
