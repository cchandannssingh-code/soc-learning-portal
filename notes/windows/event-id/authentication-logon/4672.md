# Windows Security Event ID 4672 - Special Privileges Assigned to New Logon

## Overview

| Field       | Value                                                                  |
| ----------- | ---------------------------------------------------------------------- |
| Event ID    | 4672                                                                   |
| Log Source  | Security                                                               |
| Category    | Privilege Assignment                                                   |
| Severity    | High                                                                   |
| Description | Generated when a new logon receives special administrative privileges. |

---

## What Does It Mean?

Event ID 4672 indicates that a newly authenticated session was assigned one or more powerful Windows privileges.

Think of Event ID 4672 as:

> "A privileged account successfully logged in."

This event is commonly generated after:

```text
4624
Successful Logon
```

---

## Authentication Flow

### Standard User

```text
4624
User Login
      ↓
No 4672
```

---

### Administrator Login

```text
4624
Successful Login
      ↓
4672
Special Privileges Assigned
```

---

## Why Is It Important?

Event ID 4672 helps identify:

* Administrator logins
* Privileged account usage
* Privilege escalation activity
* Service account abuse
* Lateral movement
* Attackers obtaining elevated access

---

## Why SOC Analysts Care

Most attackers eventually need administrative privileges.

Common attack chain:

```text
4624
Login
     ↓

4672
Privileges Assigned
     ↓

4688
Process Execution
     ↓

Persistence
```

# Privileges Deep Dive

## What Are Privileges?

Privileges determine what powerful actions a user can perform.

Think:

```text
Permissions
     ↓
Access To Objects

Privileges
     ↓
Control Of System
```

---

## SeSecurityPrivilege

### Purpose

Manage security logs and auditing.

Allows:

```text
Read Security Logs
Manage Audit Settings
```

---

### Attacker Interest

High.

Attackers may:

```text
Review Security Logs
Modify Auditing
```

---

## SeBackupPrivilege

### Purpose

Back up files regardless of permissions.

Allows:

```text
Read Protected Files
Read Sensitive Data
```

---

### Attacker Interest

Very High.

Can bypass file permissions.

Often abused to access:

```text
NTDS.dit
SAM Database
```

---

## SeRestorePrivilege

### Purpose

Restore files regardless of permissions.

Allows:

```text
Overwrite Protected Files
Restore Sensitive Data
```

---

### Attacker Interest

High.

Can be abused for persistence.

---

## SeTakeOwnershipPrivilege

### Purpose

Take ownership of objects.

Allows:

```text
Files
Folders
Registry Keys
```

to be reassigned.

---

### Attacker Interest

High.

Can bypass permission restrictions.

---

## SeDebugPrivilege

### Purpose

Debug other processes.

Allows access to:

```text
lsass.exe
```

and other protected processes.

---

### Attacker Interest

Critical.

Commonly abused for:

```text
Credential Dumping
Mimikatz Activity
```

---

## SeSystemEnvironmentPrivilege

### Purpose

Modify firmware environment variables.

Usually rare.

---

### Attacker Interest

Medium.

More common in advanced attacks.

---

## SeLoadDriverPrivilege

### Purpose

Load and unload drivers.

Allows:

```text
Kernel Driver Loading
```

---

### Attacker Interest

Critical.

Used by:

```text
Rootkits
EDR Bypass Techniques
```

---

## SeImpersonatePrivilege

### Purpose

Impersonate another user.

---

### Attacker Interest

Critical.

Commonly abused by:

```text
Potato Attacks

Juicy Potato
PrintSpoofer
RoguePotato
```

for privilege escalation.

---

## SeDelegateSessionUserImpersonatePrivilege

### Purpose

Allows delegation-based impersonation.

Usually seen on:

```text
Servers
```

and

```text
Terminal Services
```

systems.

---

### Attacker Interest

High.

Can support lateral movement scenarios.

---

## SeEnableDelegationPrivilege

### Purpose

Allows account delegation configuration.

Very powerful.

---

### Attacker Interest

Critical.

Can support:

```text
Kerberos Delegation Abuse
```

---

# Investigation Methodology

## Step 1

Identify account.

Review:

```text
Account Name
```

Questions:

* Is account privileged?
* Is account expected?

---

## Step 2

Find corresponding login.

Search:

```text
4624
```

using:

```text
Logon ID
```

---

## Step 3

Review source system.

From related:

```text
4624
```

collect:

```text
Source IP
Workstation Name
Logon Type
```

---

## Step 4

Review process creation.

Search:

```text
4688
```

using same Logon ID.

Questions:

* Was PowerShell executed?
* Was cmd.exe executed?
* Was Mimikatz observed?

---

## Step 5

Determine business justification.

Questions:

* Was admin work expected?
* Is login time normal?
* Is source host trusted?

# Interview Answer

## Q: What does Event ID 4672 indicate?

### Answer

Event ID 4672 indicates that a newly authenticated session was assigned special administrative privileges. During investigation I would identify the account involved, correlate the event with the corresponding 4624 logon event using the Logon ID, review the source system, analyze assigned privileges, and determine whether the privileged activity was expected or potentially malicious.
