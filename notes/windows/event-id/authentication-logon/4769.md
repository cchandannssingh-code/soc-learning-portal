# Windows Security Event ID 4769 - A Kerberos Service Ticket Was Requested

## Overview

| Field       | Value                                                                                 |
| ----------- | ------------------------------------------------------------------------------------- |
| Event ID    | 4769                                                                                  |
| Log Source  | Security                                                                              |
| Category    | Kerberos Authentication                                                               |
| Severity    | Informational (Can become High/Critical depending on context)                         |
| Description | Generated when a Kerberos Service Ticket (TGS) is requested from a Domain Controller. |

---

## What Does It Mean?

Event ID 4769 indicates that a user, computer, or service account requested a Kerberos Service Ticket (TGS).

A Service Ticket allows access to a specific service after a user has already obtained a TGT.

Think:

```text
4768
↓
Identity Verification

4769
↓
Access Specific Service
```

---

## Kerberos Authentication Flow

```text
User Login
    ↓

4768
TGT Requested
    ↓

TGT Issued
    ↓

4769
Service Ticket Requested
    ↓

Service Access Granted
    ↓

4624
Successful Authentication
```

---

## Why Is It Important?

4769 is heavily used for detecting:

* Kerberoasting
* Service Account Abuse
* Lateral Movement
* Suspicious Service Access
* Weak Encryption Usage
* Golden Ticket Activity
* Silver Ticket Activity

---

## Example Event

```text
Account Name:
john@test.com

Service Name:
test.com

Client Address:
10.82.171.11

Ticket Encryption Type:
0x12

Failure Code:
0x0
```

---

## Plain English Interpretation

This event means:

> User [john@test.com](mailto:john@test.com) successfully requested a Kerberos service ticket from 10.82.171.11 to access service test.com using AES256 encryption.

# Kerberos Fundamentals

## What Is a Service Ticket?

A Service Ticket (TGS) allows access to a specific service.

Example:

```text
User
 ↓

4768
Get TGT
 ↓

4769
Get Service Ticket
 ↓

SQL Server
 ↓

Access Granted
```

---

## Difference Between 4768 and 4769

| Event | Meaning                   |
| ----- | ------------------------- |
| 4768  | Request TGT               |
| 4769  | Request Service Ticket    |
| 4771  | Kerberos Failure          |
| 4624  | Successful Authentication |

# Ticket Encryption Type Deep Dive

## What Is Ticket Encryption Type?

This field identifies the encryption algorithm used to encrypt the Kerberos Service Ticket (TGS).

Example:

```text
Ticket Encryption Type: 0x12
```

This is one of the most important fields in Event ID 4769 because it is heavily used for:

* Kerberoasting Detection
* Weak Encryption Hunting
* Legacy Authentication Discovery
* Active Directory Hardening

---

## Common Encryption Types

| Value | Encryption Type | Security Level |
| ----- | --------------- | -------------- |
| 0x1   | DES-CBC-CRC     | Very Weak      |
| 0x3   | DES-CBC-MD5     | Very Weak      |
| 0x11  | AES128          | Good           |
| 0x12  | AES256          | Best           |
| 0x17  | RC4-HMAC        | Weak / Legacy  |

---

## Ticket Encryption Type = 0x12

Example:

```text
0x12
```

Meaning:

```text
AES256-CTS-HMAC-SHA1-96
```

This is Microsoft's preferred Kerberos encryption.

Benefits:

* Strong encryption
* Resistant to modern attacks
* Recommended by Microsoft

---

## Ticket Encryption Type = 0x17

Example:

```text
0x17
```

Meaning:

```text
RC4-HMAC
```

High-interest value.

Commonly seen during:

* Legacy Systems
* Misconfigured Service Accounts
* Kerberoasting Activity

---

### Why Analysts Care

Many Kerberoasting attacks specifically target:

```text
RC4-HMAC
```

because it is easier to crack offline.

---

## Ticket Encryption Type = DES

Examples:

```text
0x1
```

```text
0x3
```

Very high risk.

DES should no longer exist in modern environments.

Investigate immediately.

---

# Session Encryption Type

## Purpose

Defines encryption used for communication after ticket issuance.

Example:

```text
Session Encryption Type: 0x12
```

Normally matches:

```text
Ticket Encryption Type
```

---

## Why It Matters

Mismatch between:

```text
Ticket Encryption Type
```

and

```text
Session Encryption Type
```

can indicate:

* Legacy systems
* Compatibility issues
* Misconfigurations

# Advertized Etypes Deep Dive

## What Are Advertized Etypes?

These are encryption algorithms supported by the client.

Example:

```text
AES256-CTS-HMAC-SHA1-96
AES128-CTS-HMAC-SHA1-96
RC4-HMAC-NT
RC4-HMAC-NT-EXP
RC4-HMAC-OLD-EXP
```

Think:

> "These are the encryption methods the client is willing to use."

---

## Example Analysis

```text
AES256
AES128
RC4
```

Meaning:

Client supports both modern and legacy encryption.

Normal.

---

## Suspicious Example

```text
RC4 Only
```

Possible:

* Legacy OS
* Legacy Application
* Forced Downgrade

Requires review.

---

## DES Present

Example:

```text
DES-CBC-MD5
```

Modern environments should not use DES.

Questions:

* Why is DES enabled?
* Which system requires DES?
* Can DES be removed?

# Kerberoasting Deep Dive

## What Is Kerberoasting?

Kerberoasting is an attack where an attacker requests Kerberos Service Tickets for service accounts and attempts to crack them offline.

---

## Attack Flow

```text
Attacker Authenticates
         ↓

4769
Requests Service Ticket
         ↓

Receives Ticket
         ↓

Extracts Hash
         ↓

Offline Cracking
```

---

## Why 4769 Is Important

Kerberoasting almost always generates:

```text
4769
```

before cracking begins.

---

## Common Indicators

### RC4 Ticket

```text
Ticket Encryption Type:
0x17
```

High-interest.

---

### Large Number Of Service Tickets

Example:

```text
User Requests:
MSSQLSvc
HTTP
HOST
LDAP
CIFS
```

within a short time.

Possible reconnaissance.

---

### Rare Service Access

Example:

```text
Helpdesk User
```

requesting:

```text
MSSQLSvc/FinanceDB
```

May indicate attack activity.

---

# Golden Ticket Detection

## What Is Golden Ticket?

A forged Kerberos TGT created using the KRBTGT account hash.

---

## Typical Indicators

* Unusual ticket lifetime
* Impossible account activity
* Suspicious domain access
* Missing expected 4768 activity

---

## Investigation Questions

* Was a TGT legitimately issued?
* Is account behaving normally?
* Does activity align with previous logons?

---

# Silver Ticket Detection

## What Is Silver Ticket?

Forged service ticket targeting a specific service.

---

## Typical Indicators

```text
4769 Activity
```

without expected:

```text
4768 Activity
```

May indicate ticket forgery.

# Threat Hunting Opportunities

## Hunt 1 - RC4 Usage

Search:

```text
4769
AND TicketEncryptionType=0x17
```

Purpose:

Identify Kerberoasting candidates.

---

## Hunt 2 - DES Usage

Search:

```text
4769
AND TicketEncryptionType=0x1
```

or

```text
4769
AND TicketEncryptionType=0x3
```

Purpose:

Identify weak encryption.

---

## Hunt 3 - High Volume Service Ticket Requests

Search:

```text
4769
```

Group By:

```text
Account Name
```

Questions:

* Is user requesting unusually high numbers of tickets?
* Is enumeration occurring?

---

## Hunt 4 - Rare Service Access

Search:

```text
4769
```

Review:

```text
Service Name
```

Purpose:

Identify unusual service access patterns.
