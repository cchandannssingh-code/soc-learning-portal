# Windows Security Event ID 4776 - The Computer Attempted to Validate the Credentials for an Account

## Overview

| Field       | Value                                                                                          |
| ----------- | ---------------------------------------------------------------------------------------------- |
| Event ID    | 4776                                                                                           |
| Log Source  | Security                                                                                       |
| Category    | Authentication / NTLM                                                                          |
| Severity    | Informational (Can become High/Critical depending on context)                                  |
| Description | Generated when a Domain Controller attempts to validate credentials using NTLM authentication. |

---

## What Does It Mean?

Event ID 4776 indicates that a system attempted to validate credentials using the NTLM authentication protocol.

This event is usually generated on:

```text
Domain Controller
```

and records whether NTLM authentication succeeded or failed.

Think of Event ID 4776 as:

> "Windows checked a username and password using NTLM."

---

## Why Is It Important?

Event ID 4776 helps analysts identify:

* Password guessing attacks
* Brute force attacks
* Password spraying attacks
* Legacy authentication usage
* NTLM-based lateral movement
* Authentication failures

---

## Authentication Flow

```text
User Enters Credentials
          ↓
System Uses NTLM
          ↓
Domain Controller Validates Credentials
          ↓
Event ID 4776 Generated
          ↓
Success or Failure Returned
```

---

## Why SOC Analysts Care About 4776

Many attacks begin with credential validation.

Example:

```text
4776
Credential Validation
         ↓

4624
Successful Login
         ↓

4672
Privileges Assigned
```

Or:

```text
4776
Failed Validation
         ↓

4776
Failed Validation
         ↓

4776
Failed Validation
         ↓

4624
Success
```

Possible:

```text
Brute Force Attack
```

---

## Example Event

```text
Authentication Package:
MICROSOFT_AUTHENTICATION_PACKAGE_V1_0

Logon Account:
John

Source Workstation:
DESKTOP-PC

Error Code:
0xC0000064
```

---

## Plain English Interpretation

This event means:

> The Domain Controller received an NTLM authentication request for account John from workstation DESKTOP-PC, but credential validation failed because the account does not exist.

---

# NTLM Authentication Overview

## What Is NTLM?

NTLM stands for:

```text
NT LAN Manager
```

It is Microsoft's legacy authentication protocol.

---

## Preferred Authentication

Modern environments should use:

```text
Kerberos
```

instead of:

```text
NTLM
```

whenever possible.

---

## When NTLM Is Common

* Legacy Applications
* Workgroup Systems
* Older Servers
* Cross-Forest Authentication
* Local Account Authentication
* Pass-the-Hash Scenarios

---

## NTLM vs Kerberos

| Feature                     | Kerberos | NTLM       |
| --------------------------- | -------- | ---------- |
| Modern Authentication       | Yes      | No         |
| Preferred by Microsoft      | Yes      | No         |
| Supports Delegation         | Yes      | Limited    |
| Vulnerable to Pass-the-Hash | Less     | More       |
| Requires Domain Controller  | Yes      | Not Always |

---

# Key Fields Summary

| Field                  | Description                  |
| ---------------------- | ---------------------------- |
| Authentication Package | Authentication provider      |
| Logon Account          | Username being validated     |
| Source Workstation     | System requesting validation |
| Error Code             | Success or Failure reason    |

# Authentication Package

## Purpose

Indicates which authentication provider processed the request.

Example:

```text
MICROSOFT_AUTHENTICATION_PACKAGE_V1_0
```

---

## What Does It Mean?

This is Microsoft's NTLM authentication provider.

For Event ID 4776 this value is almost always:

```text
MICROSOFT_AUTHENTICATION_PACKAGE_V1_0
```

Normal.

---

## Investigation Notes

Questions:

* Why is NTLM being used?
* Could Kerberos be used instead?
* Is legacy software involved?
* Is NTLM expected in this environment?

---

# Logon Account

## Purpose

Account whose credentials were validated.

Example:

```text
John
```

This is NOT necessarily the user sitting at the workstation.

This is the account being checked by the Domain Controller.

---

## Investigation Questions

* Is account valid?
* Is account privileged?
* Is account disabled?
* Is account locked?
* Is account recently created?

---

## High-Risk Accounts

Examples:

```text
Administrator
```

```text
Domain Admin
```

```text
Service Accounts
```

Require closer review.

# Source Workstation Deep Dive

## What Is Source Workstation?

Source Workstation identifies:

> Which system requested NTLM credential validation.

Think of it as:

```text id="m1q7kp"
Who Asked The Domain Controller
To Validate Credentials?
```

---

## Example

```text id="ykn7rv"
Source Workstation:
DESKTOP-PC
```

Meaning:

```text id="4jxyb2"
DESKTOP-PC
      ↓
Sent NTLM Authentication Request
      ↓
Domain Controller Validated Credentials
```

---

## Why It Matters

Useful for:

* Brute Force Investigations
* Password Spraying Detection
* Lateral Movement Analysis
* Asset Attribution
* Threat Hunting

---

## Investigation Questions

* Is workstation known?
* Is workstation managed?
* Is workstation compromised?
* Is workstation expected to authenticate as this user?

---

## Example Investigation

```text id="aobk3y"
Account:
Administrator

Source Workstation:
HR-LAPTOP-01
```

Questions:

* Why is HR laptop authenticating as Administrator?
* Is administrator expected on this device?

---

## Blank Source Workstation

Example:

```text id="9b6hfh"

-
```

Possible Causes:

* Internal system authentication
* Incomplete audit information
* Legacy application behavior

Not automatically suspicious.

# Brute Force Detection

## What Is Brute Force?

Attacker repeatedly tries passwords against one account.

---

## Example Pattern

```text id="6dhz0x"
4776
John
0xC000006A

4776
John
0xC000006A

4776
John
0xC000006A

4776
John
0xC000006A
```

Meaning:

```text id="kmcwsr"
Same Account
Different Password Attempts
```

Possible brute force.

---

## Analyst Questions

* How many attempts?
* Same source workstation?
* Did account eventually authenticate?

---

## Successful Brute Force

```text id="7ryywr"
4776
Bad Password

4776
Bad Password

4776
Bad Password

4776
Success
```

Then:

```text id="spq3pi"
4624
```

Very high priority.

---

# Password Spray Detection

## What Is Password Spraying?

Attacker tries:

```text id="4r6ok3"
One Password
Against Many Accounts
```

---

## Example

```text id="g9xms6"
4776 User1
0xC000006A

4776 User2
0xC000006A

4776 User3
0xC000006A

4776 User4
0xC000006A
```

Same workstation.

Same time period.

Possible:

```text id="1nbwls"
Password Spray Attack
```

---

## Why It Matters

Password spraying often bypasses:

```text id="b8oxfa"
Account Lockout Policies
```

---
